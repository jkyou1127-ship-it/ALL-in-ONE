## 등록 절차 (신청 -> 승인)

라이선스는 관리자가 일방적으로 내려주는 게 아니라, **본인이 조건을 실제로 달성한 뒤 신청 -> 관리자가 검토해
승인**하는 방식으로 등록됩니다 (OBD Cube의 "대회 주최 신청 -> 관리자 승인"과 같은 패턴).

1. 관리자가 "라이선스 조건 관리"에서 종목/레벨별 기준을 먼저 등록 (예: `3x3x3 큐브 | 15.00`, `7.5 Reflection | 95.00%`)
2. 로그인한 사용자는 "신청 조건"에서 현재 조건을 확인하고, 그 조건을 실제로 달성했을 때 "신청하기"에서
   종목/레벨을 고르고 본인이 달성한 기록/정확도를 입력해 신청
3. 관리자가 "신청 승인 대기" 목록에서 신청 내용(달성값 vs 기준값)을 검토해 **승인**하면, 그 항목이 신청자의
   라이선스 카드에 반영되고(최초 승인 시 라이선스 번호 자동 발급) 상태가 "승인됨"으로 바뀜. **반려**하면
   사유와 함께 반려 처리되고 라이선스에는 반영되지 않음
4. 신청자는 "내 신청 현황"에서 본인 신청의 심사 상태(심사 중/승인됨/반려됨)를 확인 가능, 심사 중인 신청은
   직접 취소 가능
5. 관리자는 "사용자별 라이선스 조회/회수" 패널에서 닉네임으로 검색해 이미 등록된 라이선스를 회수(비활성화)할
   수도 있음 — 회수해도 발급 번호와 기록은 남아있고 다시 승인하면 재사용됨
6. 같은 패널에서 라이선스별 **등급**(자유 텍스트 — 예: `1급`, `초급/중급/고급` 등 원하는 체계로)을 입력·수정
   가능. 최초 승인으로 라이선스가 한 번 발급된 뒤에만 등급을 적을 수 있으며, 라이선스 카드에 표시됨

## 주요 기능

- 로그인하면 본인의 **C License / A License** 카드 두 개를 확인 가능 (미발급이면 "미발급" 표시)
- 각 카드에는 발급 번호, 발급일, 종목별 기록(C) 또는 레벨별 정확도(A) 목록이 표시됨
- 로그인/회원가입은 `obdcube`와 완전히 같은 방식(닉네임 2~16자, 중복 확인, OBD ID 자동 발급)을 씁니다

## Firebase 설정

`timer`, `obdcube`와 같은 Firebase 프로젝트를 공유합니다. 최초 설정 방법은
[`../obdcube/README.md`](../obdcube/README.md)의 "Firebase 프로젝트 설정" 절을 참고하세요. 이 앱의 설정 파일은
[`public/js/firebase-config.js`](./public/js/firebase-config.js)이며, 다른 프로젝트를 쓰려면 `timer`/`obdcube`
설정 파일과 함께 값을 맞춰줘야 합니다.

Firestore 보안 규칙은 세 앱이 공유하는 [`../obdcube/firestore.rules`](../obdcube/firestore.rules)에 정의되어
있습니다 — `licenses/{uid}`(본인은 읽기만, 쓰기는 관리자만), `licenseRequirements/{typeKey}`(누구나 읽기,
쓰기는 관리자만), `licenseApplications/{appId}`(신청은 본인만 생성, 승인/반려는 관리자만, 심사 중인 본인
신청 취소는 본인도 가능).
